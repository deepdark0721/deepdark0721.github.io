互联不等于可信：外滩大会「可信智能体网络」现场

2026-09-11上海黄浦世博园区 C8 馆14:00–16:00

智能体已经能互相连接。这一场论坛讨论的是：连接之后，凭什么互信。整场建立在一个判断上——协议解决了怎么连，解决不了该不该信。
82%
攻击实验中伪造 Agent Card 的成功率
旅游 82.0% · 医疗 81.6% · 金融 82.8%

这个数字意味着什么

Agent Card 是智能体自报身份的卡片——我是谁、我能干什么。现场攻击实验显示，对面大约五次里有四次没法分辨真假。一个智能体说自己是银行客服，你很难当场识破。

口径说明：82% 取自现场投影页。机器转写曾误记为 2%，以现场图为准。此数据来自该场攻击实验，不推广为所有场景的普遍攻击率。

五个要素：缺一个，互联就停在「能连上」

要素一句话
身份可验它是谁创建的、代表谁行动，必须能验证而不是自称
权限可控能访问什么、能做什么，被明确限制
数据可护流转中的数据有保护，不随连接裸奔
行为可审计干过什么留得下记录
结果可追责出了事能定位到责任主体

逐场要点（六场演讲 + 圆桌）

致辞：从「会说」走向「会做」

智能体正在从只会回答问题，变成跨应用找货、下单、调设备的执行者。越靠近现实世界，身份、授权、数据保护、过程留痕和责任归属越重要——可信不能等功能做完再补，得是地基。

身份声明必须被独立验证

蚂蚁集团安全实验室的判断：任务跨系统时，协议管连接，连接之上还有身份、数据、工具、委托、权限五道关口。82% 的伪造成功率证明——自称的不算，验过的才算。

标准、OS、身份、汽车、硬件：五条工程路径

  • 标准：没有统一术语和测试方法，互联就停在点对点适配。协议价值最终要靠测出来，不是靠文档写出来。
  • 操作系统：一次笼统授权容易被扩张成长期高权限。要把主体、目的、资源和有效期绑在一起，让每次委托可约束、可记录、可撤销。
  • 可信身份：名称和能力说明都可能被冒用，要把身份凭证、细粒度授权和行为日志串成链条。
  • 汽车智能体：连接导航、车控、账号、支付，任何一步误解或越权都可能放大成现实风险。答案有三条——不默认相信模型输出；按任务风险设权限与人工接管；安全设计覆盖模型到硬件五层。
  • 机密计算：把「推定可信」改成「可验证可信」——释放敏感数据之前，先验证代码是否真的跑在预期环境里。

圆桌共识：三条

  1. 身份必须连接责任——智能体的名字和自报能力不足以建立信任，要知道它由谁创建、代表谁行动、出事找谁
  2. 授权要细、短、可撤销——低风险可逆的任务可以自动化，高风险或不可逆的动作要更强验证或人工接管
  3. 规模化需要共同基础设施——身份、标准、硬件可信根、运行时约束必须协同
「智能体名称或自报能力不足以建立信任。平台需要知道它由谁创建、代表谁行动、凭什么获得权限。」 — 圆桌共识（现场图 PM-076）

对个人的意味

产业在修整条链的重工业段，你在补自己这一小段，用的是同一套逻辑：

论坛讲的基础设施你的个人动作
可验证身份装东西验来源，不装来路不明的包
授权最小化、限时、可撤销高风险动作人工确认，不给永久授权
审计与追责改前归档，推送前过审批
不默认相信模型输出模型是建议者，不是决策者

开两吨重的机器都这么防，你电脑上的删除和群发更该这么防。

同日上午的企业视角（补充）

阿里 Demo Day 上，亿格云把企业 AI 风险拆成三类：看不见（谁在用哪些模型、数据流向哪里）、审不清（是否越权）、管不住（缺细粒度控制）。个人尺度不需要这套系统，但发现 → 审计 → 控制的顺序值得记住——先看得见，才审得清；审得清，才管得住。
